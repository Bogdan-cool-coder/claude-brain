# Brain Protocol — Always-On Rules (v3.0)

> Этот файл мержится автоматически при подключении plugin. МИНИМАЛЬНЫЙ набор правил, которые работают ВСЕГДА. Полная методика — skill `brain-protocol`.

## 1. 🧠 ПРОТОКОЛ НЕПРЕРЫВНОСТИ

### При каждом запуске сессии
1. Найти `.claude/brain.conf` в корне проекта. Нет — предложить настройку (skill `brain-setup`).
2. Прочитать `SESSION_STATE.md` (`$VAULT/4. Активная работа/SESSION_STATE.md`).
3. Есть незавершённое (строка `→ Следующий шаг:`) — продолжить с него.
4. Для методики работы с vault — skill `brain-protocol`.

### После сжатия контекста (выполнить сразу, без вопросов)
1. Прочитать этот блок + SESSION_STATE.md.
2. Найти строку `→ Следующий шаг:`.
3. Продолжить С ЭТОГО шага. `compression_count` уже поднят pre-compact хуком (в Desktop — поднять вручную).
4. Первое сообщение = «Далее — [конкретное действие из STATE]».

**ЗАПРЕЩЕНО** после сжатия: спрашивать «на чём остановились», пересказывать сделанное, менять план, пропускать шаги.

### Каждые ~5 сообщений
Обновить STATE: `last_updated`, строка `→ Следующий шаг:`, изменённые файлы.

## 3. АБСОЛЮТНЫЕ ПРАВИЛА

1. STATE обновляется ДО и ПОСЛЕ значимого шага.
2. Первое действие сессии = чтение STATE.
3. Правка модуля без чтения `2. Модули` + `3. Журнал` = запрещено.
4. Завершённый юнит работы = запись в `3. Журнал/`.
5. `→ Следующий шаг:` без имени файла/действия = невалидно.
6. План — в STATE/Планах, не в контексте.
7. Vault побеждает контекст при конфликте.
8. **SESSION_STATE один — дубль не создавать** (реорганизация vault → `mv`, не copy).
9. **Готовые файлы — точечные правки**, без широких регенеративных проходов.
10. grep before implement — ВСЕГДА искать по кодовой базе перед новым кодом.

## 4. ЭКОНОМИЯ ТОКЕНОВ

- `grep` перед реализацией (≈100 токенов vs ~70K на дубль).
- `--quiet`, `| tail -n 20` для build/test; `grep -n` → читать только нужный диапазон.
- После сжатия — перед любым Edit перечитать «Заметки/контекст» в STATE.
