# Brain Protocol — Always-On Rules

> Этот файл мержится автоматически при подключении plugin. Содержит МИНИМАЛЬНЫЙ набор правил, которые должны работать ВСЕГДА.

## 1. ПРОТОКОЛ НЕПРЕРЫВНОСТИ

### При каждом запуске сессии

1. Найти `brain.conf` в корне проекта (`.claude/brain.conf`). Если нет — спросить пользователя о настройке (skill `brain-setup`).
2. Прочитать `SESSION_STATE.md` по пути из brain.conf.
3. Если есть незавершённая задача (строка с →) — продолжить с этого шага.
4. Прочитать skill `brain-protocol` для полной методики работы с vault.

### После сжатия контекста

Claude ОБЯЗАН выполнить немедленно, без вопросов:
1. Прочитать этот файл (CLAUDE.md)
2. Прочитать SESSION_STATE.md
3. Найти строку с → в плане
4. Инкрементировать compression_count
5. Первое сообщение = «Далее — [конкретное действие из STATE]»

**ЗАПРЕЩЕНО** после сжатия: спрашивать «на чём остановились», пересказывать сделанное, менять план, пропускать шаги.

### Каждые 5 сообщений

Обновить STATE: last_updated, прогресс плана, изменённые файлы.

## 2. АБСОЛЮТНЫЕ ПРАВИЛА

1. STATE обновляется ДО и ПОСЛЕ каждого шага
2. Первое действие при запуске = чтение STATE
3. Каждое изменение кода = запись в журнал (3. Журнал/)
4. План ТОЛЬКО в STATE, не в контексте
5. «Следующее действие» без имени файла = невалидно
6. Vault побеждает контекст при конфликте
7. ACTIVE TASK = 1, остальные однострочники в очереди
8. grep before implement — ВСЕГДА искать по кодовой базе перед написанием нового кода
9. После сжатия — прочитать «Проверено/Найдено» в STATE перед любым Edit

## 3. ЭКОНОМИЯ ТОКЕНОВ

- `grep` перед реализацией (100 токенов vs 70K если написать заново)
- `--quiet`, `| tail -n 20` для build/test команд
- `grep -n` для номеров строк, затем читать только нужный диапазон
- Не выводить целые файлы если нужны конкретные строки
